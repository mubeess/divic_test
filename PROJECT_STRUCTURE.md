# Project Structure Documentation

This document outlines the purpose of key configuration files and directories within this React Native project.

## Configuration Files

*   **`.eslintrc.js`**: This file configures ESLint, a static code analysis tool used to identify problematic patterns found in JavaScript/TypeScript code. It helps maintain code quality and consistency.
*   **`.prettierrc.js`**: This file configures Prettier, an opinionated code formatter. It enforces a consistent code style across the project, reducing debates over formatting and improving readability.
*   **`babel.config.js`**: This file configures Babel, a JavaScript compiler. Babel allows developers to use newer JavaScript features that may not yet be supported by all environments by transpiling them into compatible versions. In React Native, it's crucial for transforming JSX and modern JavaScript.
*   **`jest.config.js`**: This file configures Jest, a JavaScript testing framework. It defines how tests are discovered, run, and reported.
*   **`metro.config.js`**: This file configures Metro, the JavaScript bundler for React Native. It defines how the JavaScript code and its dependencies are bundled together to be run on the target devices or simulators.
*   **`tsconfig.json`**: This file configures the TypeScript compiler (tsc). It specifies the root files and the compiler options required to compile a TypeScript project.
*   **`package.json`**: This is a core file in any Node.js project, including React Native. It lists project dependencies, scripts (for building, testing, running, etc.), and other metadata about the project.
*   **`Gemfile`**: This file is used by Bundler, a dependency manager for Ruby. In React Native projects, it's often related to managing dependencies for iOS development tools like CocoaPods.
*   **`yarn.lock`**: This file automatically generated by Yarn, a package manager. It locks down the versions of dependencies to ensure consistent installations across different environments and developers.
*   **`app.json`**: This file contains configuration specific to the application itself, such as its display name, version, and potentially settings for Expo if the project uses it.
*   **`app_theme.json`**: This file likely defines the application's theme, such as colors, fonts, and spacing, to ensure a consistent look and feel throughout the app.

## Native Project Directories

*   **`android/`**: This directory contains the native Android project code and configuration. Developers might need to work in this directory for Android-specific configurations, custom native modules, or when building the Android application.
*   **`ios/`**: This directory contains the native iOS project code and configuration (typically an Xcode project). Similar to the `android/` directory, developers interact with this for iOS-specific settings, native modules, and building the iOS application.

## Entry Points

*   **`index.js`**: This is typically the main entry point for a React Native application. It registers the root component of the application (often `App.tsx`) with `AppRegistry` from React Native, making it the starting point for the JavaScript execution.
*   **`App.tsx`**: This file usually defines the root React component of the application. It's where the main navigation, layout, and overall structure of the app are typically set up. The `.tsx` extension indicates it's a TypeScript file using JSX.

## Other Directories

*   **`assets/`**: This directory is commonly used to store static assets for the application, such as images, fonts, and sound files.
*   **`__tests__/`**: This directory typically contains test files for the application, often using a testing framework like Jest. It's a common convention for co-locating tests with the code they are testing or grouping them together.

## README.md

*   **`README.md`**: This Markdown file provides a general overview of the project. It usually includes information on how to set up, build, run, and test the project, as well as details about its purpose, features, and contribution guidelines. It's the first place a new developer or user would look to understand the project.

## State Management and API Interactions (Redux)

The application utilizes Redux and Redux Toolkit for robust state management and streamlined API interactions. The core of this setup resides in the `src/redux/` directory.

1.  **Overall Redux Structure**:
    *   **`src/redux/index.ts`**: This file is the main entry point for the Redux store configuration. It likely uses Redux Toolkit's `configureStore` function to set up the global store, combining various reducers and middleware. The `Provider` component in `index.js` makes this store available to the entire application.
    *   **`src/redux/reducers/index.ts`**: This file is expected to combine all the different reducers into a single root reducer that is then passed to the store. While the project heavily uses the "slice" pattern (which includes reducers), this file would be the traditional place to use `combineReducers`.

2.  **API Interaction with RTK Query (`src/redux/api/apiSlice.ts`)**:
    *   **`apiSlice.ts`**: This file leverages Redux Toolkit Query (RTK Query) via `createApi` to manage API interactions. This approach automates data fetching, caching, and request lifecycle management.
    *   **`baseQuery`**: It configures `fetchBaseQuery` with a `baseUrl` (imported from `../../utils/config`) for all API requests.
    *   **`prepareHeaders`**: This function dynamically sets request headers, including retrieving a token (`sid`) and user credentials from `AsyncStorage` to include in cookies for authenticated requests. This indicates that session management is handled via cookies.
    *   **Endpoints**:
        *   `loginUser`: A `mutation` endpoint for handling user login (`POST` request to `/method/login`). It uses `transformResponse` to extract cookies from the response headers, likely for session persistence.
        *   `getShipMents`: A `query` endpoint to fetch a list of shipments (`GET` request to `/method/frappe.client.get_list?doctype=AWB&fields=["*"]`).
        *   `getFilters`: A `query` endpoint to fetch AWB statuses, likely for filtering shipments (`GET` request to `/method/frappe.client.get_list?doctype=AWB Status&fields=["*"]`).
    *   **Generated Hooks**: RTK Query automatically generates React hooks for these endpoints (e.g., `useLoginUserMutation`, `useGetShipMentsQuery`, `useGetFiltersQuery`), which components can use to trigger API requests and access their state (data, loading, error).
    *   **Caching and State**: RTK Query manages the caching of fetched data. The state related to API requests (loading status, fetched data, errors) is automatically handled by this slice and integrated into the main Redux store under the `api` reducer path (as defined by `reducerPath: 'api'`).

3.  **Feature-Specific State Management with Slices (`src/redux/slices/userSlice.ts`)**:
    *   **`userSlice.ts`**: This file defines a Redux "slice" using `createSlice` from Redux Toolkit to manage user-related state.
    *   **`initialState`**: It defines the initial state for user information (name, image, token).
    *   **Reducers (within the slice)**:
        *   `setUser`: An action and reducer that updates the `user` state with the provided payload (of type `UserType`).
    *   **Actions**: `createSlice` automatically generates action creators (e.g., `setUser`) that can be dispatched from anywhere in the app to update the user state.
    *   **Selectors**:
        *   `userSelector`: A selector function to efficiently retrieve the `user` state from the global Redux state.
    *   **Reducer Export**: The slice's reducer (`userSlice.reducer`) is exported to be combined into the root reducer in `src/redux/reducers/index.ts`.

4.  **Traditional Reducers (`src/redux/reducers/`)**:
    *   The presence of a `src/redux/reducers/` directory and an `index.ts` file within it suggests that if there were any "traditional" Redux reducers (written separately from actions and action types), they would be combined here. However, with the adoption of Redux Toolkit slices (`userSlice.ts` and `apiSlice.ts` which internally creates its own reducer), this directory might primarily serve to combine the reducers generated by these slices rather than housing many standalone reducer functions.

In summary, the application employs a modern Redux setup using Redux Toolkit. API calls are declaratively handled by RTK Query in `apiSlice.ts`, which simplifies data fetching and caching. Other specific pieces of application state, like user information, are managed in dedicated slices like `userSlice.ts`. These slices encapsulate their reducers and action creators, promoting a more organized and maintainable state management architecture.

## Overall Architecture Summary

This React Native application follows a well-structured, component-based architecture, leveraging modern tools and practices for development, state management, and API interaction.

*   **Foundation**: Built with React Native, allowing for cross-platform development (iOS and Android) from a single JavaScript/TypeScript codebase. Native-specific code and configurations are managed within the `ios/` and `android/` directories. Essential build and configuration tools like Babel, ESLint, Prettier, and Metro are defined at the root level.

*   **Entry and Initialization**: The app starts with `index.js`, which sets up crucial global providers: Redux for state management (`Provider` from `react-redux`) and React Native Paper for UI theming (`PaperProvider`). It then registers `App.tsx`, the root React component.

*   **UI and Components**: The UI is composed of reusable components located in `src/components/` (e.g., Buttons, Inputs, Header) and screen-specific components within `src/screens/`. `App.tsx` handles the initial splash screen (`AnimatedSplashScreen`) before handing over to the main navigation. Static assets like images and SVGs are managed in `assets/` and `src/assets/`.

*   **Navigation**: App navigation is managed by `@react-navigation` within `src/navigations/`. `AppNavigation.tsx` is the central navigation setup, likely using a main stack navigator (`MainAppStack`) to control the overall flow. This stack manages transitions between authentication screens (`src/screens/Authentication/`) and the main application content, which is primarily structured using a bottom tab navigator (`DashboardBottomTab` in `src/navigations/Tabs/`).

*   **State Management**: Global application state is managed using Redux with Redux Toolkit, as configured in `src/redux/`. This includes:
    *   User authentication state and details (`src/redux/slices/userSlice.ts`).
    *   API data fetching, caching, and request status via RTK Query (`src/redux/api/apiSlice.ts`).
    The Redux store is configured in `src/redux/index.ts` and reducers are combined in `src/redux/reducers/index.ts`.

*   **API Interaction**: Backend communication is handled by RTK Query, defined in `src/redux/api/apiSlice.ts`. It provides a centralized way to define API endpoints (e.g., login, fetching shipments), manage request/response cycles, and automatically handle caching and state updates related to API data. Authentication tokens/cookies are managed via `AsyncStorage` and automatically included in API request headers.

*   **Utilities and Configuration**: General utility functions, TypeScript type definitions, and application-wide configurations (like colors and API base URLs) are stored in `src/utils/`.

*   **Development and Testing**: The project is set up for testing with Jest (`jest.config.js`) and uses TypeScript (`tsconfig.json`) for enhanced code quality and maintainability.

In essence, the application boots up, initializes providers and theming, displays a splash screen, then transitions to a navigation system that either directs the user to authentication or the main dashboard. Reusable components build the UI of various screens, and global state (including user data and API responses) is managed centrally by Redux. RTK Query streamlines communication with the backend, creating a reactive and maintainable application structure.
